## 3. The two rules as built

### B1 — "QUESTION" ×N re-opens a list

A step **enters a level** when it is a **spine answer** (a DECISION edge always moves) or a **child prompt answered OUI**. A child answered **NON does not** — it only walks to the next sibling. `rewind(N)` finds the N-th most recent entering step, undoes it and everything after, and its own question is asked again. Fewer than N entering steps → the very first question, **not** an error. `DSA_INVALID_REWIND` now only for N outside 1–3 or an empty path (block 10 was updated for exactly that).

One definition: `packages/core/src/rules.ts`, mirrored by `dsa_replay` (`enters_level`) + `dsa_rewind_target`.

The brief's four examples, all now tests in core, SQL and mobile:

| Scenario | ×1 asks again |
|---|---|
| CLASSE 1 → OUI, "Premier homme" → NON, "Le meurtrier" → NON | **CLASSE 1**; NON then moves to the next sibling above |
| PENTATEUQUE → OUI, LIE A ADAM → **NON** *(mistake)*, now at LIE A ABRAHAM | **PENTATEUQUE** — the question that opened this list |
| the same, ×2 / ×3 | **HOMME** / **ANCIEN** |
| right after a spine answer | that same spine question (unchanged) |

Also covered: rewinding at the start, two NON not being levels, a rewind after a wrong name call (a refused name is not a step), undone steps staying recorded, one rewind in the stats.

**In the app:** the Tireur's hint states the rule; ×1/×2/×3 are enabled as soon as one answer exists (the old UI disabled `N > path.length`, no longer the rule); the Découvreur reads *« Le Tireur demande de revenir à « PENTATEUQUE ? ». »*, or *« … de tout reprendre depuis la première question. »*. The voice intent and the Découvreur's own "Revenir" are unchanged.

### B7 — practising one part of the book

`settings.scope` is an array of section node ids, stored **only when non-empty** (so an untouched game's settings stay byte-identical to before 0010). It restricts **only which name is drawn**; the questions still start at ANCIEN. `dsa_redraw_secret` stays inside it and `dsa_rematch` keeps it. New RPC **`dsa_list_sections`** (label, parent, depth, count) returns **no name, no clue, no leaf**. Validation: `DSA_INVALID_SETTINGS` for an unknown section (a CHARACTER included), non-array, non-uuid or unknown key; `DSA_NO_PLAYABLE_SECRET` for an empty union. The game screen writes « Partie : LES EVANGILES » from `scope_labels`. The offline service mirrors all of it.

## 5. Deviations

1. **`dsa_normalize_settings` changed signature** to `(jsonb, uuid)` — a scope can only be validated against a graph. The one-arg version is **dropped**, because a defaulted second parameter would make every call ambiguous. It is internal (revoked since 0006), so no client is affected; block 12 updated.
2. **The whole book stores no `scope` key**, rather than `[]`. Keeps old `settings` byte-identical, so no existing assertion changed. `scope_labels` is `[]` either way.
3. **A fix outside the brief's letter:** `toDsaError` now understands `EngineError`. The offline service runs on `@dsa/core`, which throws bare codes (`INVALID_REWIND: …`), so **every** engine failure was showing the `UNKNOWN` French line. Four lines, pre-existing, on the exact path this brief changes.
4. **"Remember the last scope" (optional) not done** — S10 owns the Réglages store it points at; a second S11-only store would just have to be unpicked. **Recommend folding into S10.**
5. **`dsa_list_sections` includes the START node**, per the brief's "every non-CHARACTER node". The app drops it in `buildTree` and offers its children as the top level: ticking everything is « Tout le livre » = the empty scope.
6. **Ticking a branch clears its children**, so the "N names" count can't double-count; covered children render ticked and disabled.
7. **Counts are computed by walking each name up to the root**, one pass — not one recursive CTE per section (~440 on the real book).
8. **The notice is driven by what this device asked for**, not by a move type: the state says nothing about *why* a path shrank, and adding a "last move" field for one banner seemed a poor trade.
